# 全圖細節載入與繪製優化

本輪以 `aa5dcc7e` 為基準，保留上一輪的邊界細節、配色、行政區選取與點擊範圍，降低下載量及重複繪製的成本。所有 259 份輪廓使用同一套處理，沒有針對香港作特殊優化。

## 實作與取捨

- `scripts/build-detail-atlas.mjs` 和 `data/outlines/*.json` 改用無損整數差分儲存輪廓；`src/outline-detail.js` 在現有的延遲載入模組內還原路徑，不增加模組請求。全部 259 份解碼後的 SVG 路徑及其他資料欄位與基準逐一相等。總 gzip 大小由 6,337,675 減至 5,365,861 bytes，減少 **15.33%**；這是整份圖集的合計，各國節省幅度不同。
- `src/compiled.js` 跳過已完整載入國家的啟動重畫。`initialCountries` 仍會補載完整行政區，以保留相鄰區域的點擊與 `detailsReady` 行為。非同步資料抵達時，由 `src/compiled-layer.js` 合併同一畫面更新週期的重畫；使用者直接改變選取時仍立即更新。
- 繪圖時使用現有的分組範圍排除遠處離島或跨日期線輪廓，保留線寬所需的邊緣餘量。只要可見孔洞集合相同，不同縮放級別即可共用描邊路徑。填色、點擊路徑、孔洞顯示門檻及先填色後描邊的次序不變。

代價是細節抵達後多一道解碼步驟。以下瀏覽器量測包含此步驟及實際畫面更新，因此下載節省與解碼成本一併計入。新輪廓資料須與本版 runtime 一起部署；本版 loader 可讀取舊格式，舊版 loader 無法讀取新格式。

## 量測方法

Chrome、1200 × 800、DPR 1、gzip、空快取，模擬 1.6 Mbps 與 150 ms 延遲。東亞、挪威及日期線附近各先暖機，再交錯執行基準與新版各五次，以下使用中位數。啟動選取分別為香港、挪威一個行政區、美國一個行政區；各自先完整載入該國行政區，因此首次顯示時間不可直接與上一輪使用不同啟動資料的報告比較。

首次顯示測至地圖建立後兩個畫面更新週期；放大等待時間測至目前視野的細節完成並呈現。所有伺服器端資料、Git 讀取與 gzip 工作都在計時前完成。預設通過條件為：全球細節 gzip 至少減少 10%，每個測試視野的細節 bytes 與等待時間均至少減少 5%，首次顯示退步不超過 `max(5%, 100 ms)`，三張對照畫面像素完全相同，且快取後平移至歐洲不再繪製遠處的美國／俄羅斯國家輪廓。

## 量測結果

| 視野 | 首次顯示：基準 → 新版 | 放大細節：基準 → 新版 | 等待縮短 | 細節下載量減少 |
| --- | ---: | ---: | ---: | ---: |
| 東亞（第 10 級） | 3,159.5 → 3,147.8 ms | 1,756.5 → 1,445.6 ms | 17.7% | 24.5% |
| 挪威（第 9 級） | 5,605.7 → 5,595.0 ms | 1,321.5 → 1,219.9 ms | 7.7% | 8.8% |
| 日期線附近（第 9 級） | 8,595.3 → 8,585.9 ms | 4,077.9 → 3,641.6 ms | 10.7% | 12.2% |

三個視野的首次顯示時間接近，均通過退步限制；本輪主要收益在放大細節的等待與後續操作，並非大幅加快首次下載。首次顯示的傳輸量因程式增量增加 578 bytes，沒有提前下載細節。三張 1200 × 800 對照畫面均為 **0 個像素差異**，各次選取紀錄與 codeword 完全一致。

啟動時的瓦片繪製由 48 次降至 24 次，移除一次重複重畫。載入美國／俄羅斯後平移至已快取的歐洲視野，再執行四次平移與縮放：遠處兩國的國家輪廓繪製由 176 次降至 0 次；路徑解析量由 1,362,727 降至 51,756 個字元；同步瓦片繪製耗時由 14.5 降至 7.8 ms。這組操作沒有額外細節請求，包含畫面更新等待的總耗時由 261.6 降至 132.3 ms。

CPU 收益並非每個視野都相同：細節階段的同步瓦片繪製中位數，東亞為 24.5 → 31.0 ms、挪威 18.8 → 20.2 ms、日期線 43.3 → 41.2 ms。此數值包含測量工具本身的計數開銷，不包含 GPU 光柵化；端到端等待時間已包含解碼、繪圖及呈現，三個視野均有改善。

原始五輪數據、通過門檻及像素結果見 [benchmark.json](../outputs/map-refinement-2/benchmark.json)；全圖無損比對見 [encoding.json](../outputs/zoom-detail/refinement2-encoding.json)；互動與接縫檢查見 [detail-test.json](../outputs/map-refinement-2/regression/detail-test.json)。

## 驗證與重現

95 項自動測試、資料驗證、套件打包檢查及瀏覽器回歸均通過。資料涵蓋 259 個地理實體、45,863 個行政區及 248 份延遲載入分片。除了效能對照，回歸檢查涵蓋桌面及手機觸控、跨世界環繞、放大縮小、點選、重設、取消、銷毀、503 失敗重試、日本離島與接縫、挪威峽灣、德法邊界、阿拉斯加和日期線。靜態匯出測試驗證套件包含相容 runtime、完整細節資料及雜湊。

```sh
npm run check
npm run validate:data
npm run pack:check
PLAYWRIGHT_MODULE=/absolute/path/to/playwright node scripts/test-map-progressive.mjs
PLAYWRIGHT_MODULE=/absolute/path/to/playwright OUTPUT_DIR=outputs/map-refinement-2/regression node scripts/test-map-detail.mjs
PLAYWRIGHT_MODULE=/absolute/path/to/playwright BENCHMARK_MODE=refinement BASELINE_REF=aa5dcc7e node scripts/benchmark-zoom.mjs
```

`PLAYWRIGHT_MODULE` 指向已安裝的 Playwright；瀏覽器測試需要 Google Chrome。原有 benchmark 預設模式保留上一輪的測量方式，第二輪需指定 `BENCHMARK_MODE=refinement`。

這些是受控本機瀏覽器結果，實際等待時間會受裝置、網路及部署方式影響。本輪降低相同細節的成本，沒有替換資料來源或增加幾何精度。修改保留於本機，尚未發佈或部署。
